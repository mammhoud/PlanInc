# Internationalisation (PI-009)

> Part of **PlanInc** — AI-powered card note-taking and planning

Two locale trees exist because the repository has two front ends:

| Tree | Belongs to | Shipped |
| --- | --- | --- |
| `runtime/public/locales/<lang>/` | the deployed runtime | **yes** |
| `src/app/public/locales/<lang>/` | the upstream React client | no |

They are not interchangeable. Editing the `src/` tree changes nothing that users
see.

## Locale set

`ar`, `de`, `en`, `es`, `fr`, `ja`, `ka`, `kab`, `ko`, `nl`, `pl`, `pt`, `ru`,
`tr`, `uk`, `zh`, `zh-TW`.

`en` is the **reference set**. Every other locale is measured against it.

## How lookups work

`runtime/public/i18n.mjs` holds the lookup layer; `runtime/public/locales/`
holds the strings. A missing key falls back to the reference locale rather than
rendering the raw key, which is why a missing translation is easy to miss in the
UI and why parity is enforced by a test instead.

```js
// runtime/public/i18n.mjs
i18n.t("some.key", { lng: "de" });
```

## Parity is enforced, not hoped for

`runtime/tests/i18n-parity.spec.mjs` asserts translation completeness as a
**build-time property**: every locale must cover the reference key set. The spec
also asserts **key uniqueness within a locale object**.

That second assertion is not theoretical. `runtime/public/i18n.mjs` once declared
`viewRecycle` and `viewArchive` twice in the same object literal; the later
declaration won, so the live-filter group's `'Bin'` silently overwrote the
toolbar's `'Recycle bin'`. Object literals do not warn about this — only a test
does.

## Adding a language

1. Create `runtime/public/locales/<code>/translation.json`.
2. Copy the reference (`en`) key set — do not invent keys.
3. Add the code wherever locales are enumerated, including the language switcher.
4. Run `make test`. The parity spec is the acceptance gate; it fails on a missing
   key, so this step is not optional.

## Adding a string

1. Add the key to `runtime/public/locales/en/translation.json`.
2. Translate it into every other locale, or the parity spec fails.
3. Use `i18n.t(...)` in `runtime/public/` — never a literal in the markup.

> When adding a key, check the object literal it lands in for a duplicate name.
> Duplicate keys in the same literal are legal JavaScript and silently discard the
> earlier value; the parity spec is what turns that into a failure.
